# 后端日志不显示问题排查指南

## 问题现象
- 前端发送请求，收到200响应
- AI正常返回内容
- 但后端控制台没有任何日志输出

## 可能的原因

### 1. 代码修改未生效
**解决方案**: 重启后端服务
```bash
# 停止当前服务（Ctrl+C）
# 重新启动
cd backend
.\venv\Scripts\activate
uvicorn main:app --reload --port 8000
```

### 2. 日志被缓冲
**解决方案**: 已添加 `sys.stdout.flush()` 和 `flush=True`

### 3. 流式响应导致日志延迟
**解决方案**: 已在多个位置添加日志，包括：
- 中间件（最早）
- 路由函数开始
- 生成器函数开始
- 每个处理步骤

## 测试步骤

### 步骤1: 测试简单端点
访问 `http://127.0.0.1:8000/test`，应该看到：
```
[TEST] 测试端点被访问
```

### 步骤2: 测试中间件
访问任何端点，应该看到：
```
============================================================
[REQUEST] GET /test
[REQUEST] 客户端: 127.0.0.1
============================================================
```

### 步骤3: 测试AI端点
发送AI消息，应该看到：
```
============================================================
[REQUEST] POST /api/v1/ai/ask/stream
[REQUEST] 客户端: 127.0.0.1
============================================================

================================================================================
[AI请求] ========== 收到新请求 ==========
...
```

## 如果仍然没有日志

### 检查1: 确认服务已重启
- 停止当前uvicorn进程
- 重新启动服务
- 确认看到 "Application startup complete"

### 检查2: 检查uvicorn日志级别
uvicorn默认会输出INFO级别的日志，如果看不到，可能是：
- 日志被重定向到文件
- 终端输出被抑制

### 检查3: 使用文件日志
如果控制台日志不显示，检查日志文件：
```bash
# 查看日志文件
cd backend
dir logs\
type logs\app_*.log
```

### 检查4: 直接测试Python输出
```bash
cd backend
python -c "import sys; sys.stdout.write('测试\n'); sys.stdout.flush(); print('测试2', flush=True)"
```

## 临时解决方案

如果日志仍然不显示，可以：
1. 使用文件日志（已在 `core/logger.py` 中配置）
2. 检查 `backend/logs/` 目录下的日志文件
3. 使用 `--log-level debug` 启动uvicorn：
   ```bash
   uvicorn main:app --reload --port 8000 --log-level debug
   ```
